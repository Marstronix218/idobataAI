# Pivot A: manual launch confirmations

`npm run launch-check` requires every item below to be ticked (`- [x]`). These are things no script can see: dashboard settings, deployment variables, and decisions. Tick an item only once it is true in **every** environment that will serve real users, and keep the id in backticks: the check looks items up by id, and a removed item counts as unticked.

- [ ] `before-user-created-hook` The Before User Created hook (`public.hook_before_user_created`, Authentication > Hooks) is enabled in every hosted Supabase project. Why: `supabase/config.toml` only enables it on the local stack; without it, an under-18 or token-less sign-up is still refused by the database backstop, but with a generic "Database error saving new user" instead of the date-of-birth message.
- [ ] `app-env` `APP_ENV` is set correctly on every deployment (`production` on production, `staging` on any staging project Vercel marks as production), and `ALLOW_SELF_ATTESTED_AGE` is unset in production. Why: the production rule in `src/lib/age/environment.ts` reads `APP_ENV` first, so a staging value on production (or a missing one on staging) changes which age verifier is allowed.
- [ ] `age-verification-provider` A real age-verification provider is implemented, registered in `src/lib/age/verifier.ts`, and selected with `AGE_VERIFIER` on production. Why: production refuses the self-attested verifier, so until a real provider exists every age check answers 503 and Pivot A sign-up is closed.
- [ ] `daily-spend-limit` `AI_DAILY_SPEND_LIMIT_USD` is set on production before `beta_full_access.enabled` is turned on. Why: the free beta gives every user Plus-level AI caps, and with the limit unset the global spend breaker is off.
- [ ] `anthropic-spend-limit` A monthly spend limit is set on the Anthropic workspace whose key production uses. Why: it is the last cap on AI cost if the app's own caps or breaker fail, and it can only be set in the Anthropic console.
- [ ] `legacy-chat-transcripts` The decision on the existing persona chat transcripts (`chat_messages`) is made and carried out: kept as they are, or purged (PLAN D14). Why: the spec says there are no chat transcripts, but the legacy ones are still stored, and nothing is deleted without the founder's decision.
- [ ] `safety-copy-review` The crisis card (web and mobile) and the `/safety` page copy are reviewed by a clinician and by counsel, including what happens when the distress check fails. Why: the distress protocol and its copy are placeholders until reviewed (PLAN D4 and §7), and `/safety` still carries its counsel-review marker.
- [ ] `billing-disabled` Billing stays disabled: no `STRIPE_*` variables and no `BILLING_PROVIDER` other than `none` on any deployment, until a cancellation-aware billing integration exists. Why: `DELETE /api/account` refuses (409) while `BILLING_PROVIDER`, `STRIPE_SECRET_KEY` or `STRIPE_WEBHOOK_SECRET` is set, so setting one turns off account deletion.
